## Findings the architect should know (already dispositioned in the contract §4)

- **G-1 — no rounding.** The Excel applies *no* rounding; the harness runs `roundingRule:"none"`
  to match. A project set to `"dollar"` rounding will *intentionally* diverge ~$0.18 on this bid.
- **G-2 — STEP 2/3 are hand-authored**, not generated by the app's parametric GC/Site-Ops driver
  model. So the engine is **not** expected to reproduce STEP 2/3 *totals* from clean inputs;
  the harness takes the 10 linked values from the sheet and ties each STEP 2/3 section subtotal
  to its STEP 4 linked row (9/10 cached match to the cent; Special Inspections is qty 0 → $0).
- **G-4 — the bid's Budget Line Items rollup is `#REF!`-broken** (112/217 rows) — the concrete
  reason the exporter rewrites BLI as computed values.
- **No engine bugs surfaced.** Every delta is a deliberate setting/boundary or a source-sheet
  defect the app already corrects.

## Where Phase 3 starts — Fail-Loud Hardening

Per the plan's **Phase 3** ("the contract made real"). **Read first:** the plan + this handoff +
`docs/correctness-contract.md` (§3 silent-escape register + the new §4), then
`src/lib/parser.ts` (≈ lines 45-50, 104-120) and `src/hooks/useFileIngestion.ts` (≈ 113-220).

**Decisions locked:** US number format; negatives can appear → honor accounting `( … )` /
trailing-leading minus as negative; **fail loud** (route to override) on anything genuinely
ambiguous — never guess.

1. **Fix #5 — sign-safe US parsing** (`parser.ts` `parseCleanFloat`, contract INV-8 / register #5).
   Rewrite so `"(1,234.50)" → -1234.50`, `"-1,234.50" → -1234.50`, `"1,234.50- " → -1234.50`,
   `"1,234.50" → 1234.50`; ambiguous → a sentinel that routes to the override interface. New
   `src/lib/__tests__/parser-numbers.test.ts`.
2. **Fix #3 — no silent row drop** (`useFileIngestion.ts` `mergeTakeoffData`, register #3). A
   parsed row with a **valid itemId but `targetIdx === -1`** must be **appended to the grid**
   (`source:'csv_import'`, all non-nullable `ProcessedTakeoffRow` fields initialized, placed in
   its division) **and** recorded on the same `MERGE_TAKEOFF_DATA` command via
   `commandHistory.pushCommand` (full inverse data → one Ctrl+Z reverses the whole merge — see
   AGENTS.md compounding-history rule). A row with **no** itemId keeps surfacing its
   classification name **and** carries its quantity into the override surface. New integration
   test under `src/hooks/__tests__/` (or `src/__tests__/`).

**Guardrails unchanged:** `calculations.ts` is the sole financial authority; all DB access via
`db.ts`; **no schema change in Phase 3**. Each fix ships red→green.

**Regression gate:** after both fixes, **the Phase 2 golden harness must still tie McKenna to
the cent** — run `npm run test` and confirm `golden-mckenna.test.ts` stays green (it will skip
on machines without the fixture; run it where the fixture is present before delivery). Then
