## B-1 — CI-safe synthetic template fixture

**Problem.** The keystone proof (`src/__tests__/golden-mckenna.test.ts`) reads the **confidential**
McKenna oracle and `describe.skipIf`s when it is absent. So on CI and any machine without the
bid file it **skips** — a regression in `src/lib/templateExtractor.ts` or in the STEP 4 summary
math could land with no machine catching it unless the fixture happens to be present.

**Fix.** Commit a small **non-confidential** workbook in the company-template format (fabricated,
round-number inputs and outputs) and run the extractor + engine tie-out against it on every
machine — the same way `src/__tests__/export-integrity.test.ts` already uses the git-tracked
blank template. The McKenna test stays as the confidential real-bid proof; the synthetic one
proves the *machinery* works everywhere.

**Done when.** A committed synthetic template ties through `computeTakeoffSummary` (and the
extractor) in CI, with the McKenna harness unchanged.

## B-2 — Born-in-app GC/Site-Ops golden

**Problem.** The McKenna harness proves the STEP 4 **summary** math to the cent, but
**deliberately does not** prove the GC/Site-Ops engine (`computePersonnelCosts` /
`computeSiteOperations`): the real bid's STEP 2/3 are hand-authored and do not follow the app's
parametric driver model (Phase 2 finding **G-2**). Those engines are only unit-tested today —
never tied end-to-end to a real estimate.

**Fix.** Once a reference estimate is created **through the app** (so STEP 2/3 are generated by
the parametric model), add a golden that ties the GC + Site Ops totals — and the 10 linked
division values they feed — to that estimate's exported workbook, reusing `templateExtractor`
and the `export-integrity` patterns.

**Done when.** A born-in-app estimate's GC + Site Ops totals reproduce to the cent through the
engine and export.

## B-3 — Rounding default decision + visibility

**Problem.** The McKenna Excel applies **no rounding**, so the harness runs `roundingRule:"none"`
to tie to the cent (Phase 2 finding **G-1**). But the app's default project rounding is
`"dollar"`. A live project left on `"dollar"` will **intentionally diverge from its source
spreadsheet by up to ~$0.50 per modifier** — correct behavior, but invisible today.

**Fix.**
1. **Decision (architect):** should the app default to `"none"` (template-faithful) or keep
   `"dollar"`? Either is defensible; the choice should be deliberate.
2. **Visibility (Phase 5 glass box):** surface the active rounding mode and the
   `validateExportReadiness` reconciliation so any rounding-driven difference is shown, never
   silent.

**Done when.** The default is chosen, and Phase 5 shows the rounding mode in the trace /
reconciliation view.
